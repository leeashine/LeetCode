# 第 2 步：两台设备的操作统计，怎样不丢不重

[← 合并的约定](01-半格三律.md) ｜ [目录](../README.md) ｜ [下一章：给标题修改排序 →](03-LWW寄存器.md)

**上一步**：知道合并需要抗重复、换序和分组。

**本课任务**：累计各处操作次数，再把只增统计扩展成可增减的笔记净增量。

**完成后**：A 做两次、B 做一次，同步后是 3；重发仍是 3，增加与减少分别保留。

**练习入口**：[GCounter](../learnning/GCounter.java)、[PNCounter](../learnning/PNCounter.java)。

## 1. 两个 3，可能代表不同经历

**假设**

手机独自做三次操作，电脑独自做三次；另一种情况下电脑只是同步手机那三次。两边屏幕都显示 3。

**问题**

收到两个 3，是相加成 6，还是保留 3？

**解释**

光看数字无法判断。需要分开记来源：`{A=3,B=2}` 表示 A 累计贡献 3 次、B 贡献 2 次，总数为 5。

保存每个写入者的累计贡献，不保存全部单次事件，可以让状态规模随写入者数增长。不同设备必须有不同 ID。

## 2. 为统计找到最初的数据结构

**假设**

现在还没有操作。第一次操作后，要记 A=1；收到别的设备后，可能出现 B、C。

**问题**

构造器要收什么、字段要存什么？为什么不只存一个 long？

**解释**

记录本地身份 replicaId，才能知道后续修改哪一栏；counts 用 Map 保存所有来源的贡献。构造器接受本地 ID，最初 counts 为空。没有某个 key 表示 0。

更新后需要保存一张新表，因此还需要接收“身份＋新 Map”的内部构造器。它保存只读快照，外部不能改旧数据。

在骨架的字段 TODO 处定义这些信息，再填写构造器。查看某来源次数的需求产生 `countOf(id)`，不知道该来源就返回 0。

## 3. 本地又做一次操作

**假设**

手机当前知道 A2/B1，又做了一次操作。它不能替电脑增加 B 那栏。

**问题**

这个动作为什么叫 increment，输入和返回应是什么？

**解释**

需求是推进自己的累计贡献，产生 increment。无参数版本表示一次操作；带 delta 版本方便一次汇总多次本地贡献。只能接收非负增加量。

流程是读本地旧值、复制 counts、修改自己一栏、返回新 GCounter。给 value 读取总数的职责，不在 increment 中同步别人。

<details>
<summary>核心变化：只增加本地分量</summary>

```java
Map<String, Long> next = new TreeMap<String, Long>(counts);
long updated = Math.addExact(countOf(replicaId), delta);
if (updated != 0) {
    next.put(replicaId, updated);
}
return new GCounter(replicaId, next);
```

</details>

参数校验先写在这个片段之前；内部构造器需先补齐。Math.addExact 检测 long 溢出，避免累计值突然回绕。

## 4. 收到手机的新快照又重发一次

**假设**

A 的记录从 A2 推进到 A3。B 已有 A2/B1，接下来连续收到 A3 两次。

```text
第一次：A2/B1 与 A3 → A3/B1
第二次：A3/B1 与 A3 → 仍 A3/B1
```

**问题**

为什么 merge 取 max，value 却求和？这两个方法由什么需求产生？

**解释**

同一来源的 A3 已包括 A2，merge 逐来源保留较大累计值，不能相加。显示总操作次数时，各来源贡献彼此独立，所以 value 求和。

先实现 merge：拷贝自己的 Map，遍历对方各 key，取 max 写入新 Map。再实现 value：遍历分量求和。state 提供只读查看，便于观察记录；它不是额外的同步算法。

## 5. 同样的信息在不同设备上

**假设**

A.merge(B) 保留 A 的本地身份，B.merge(A) 保留 B，但 counts 都是 A2/B1。

**问题**

怎样判断两边一致？本地身份也应该进 equals 吗？

**解释**

统计信息一样，应该相等。因此 equals/hashCode 比 counts，不比接收者的 replicaId。未来两边继续操作，仍分别增加自己的栏。

只比 value 也不够：A1 与 B1 都显示 1，却代表不同贡献。HashCode 与 equals 使用同一信息，state 不保留无意义的零条目，保持相等判断统一。

replicaId() 方便核对当前对象以后由谁写，直接读取本地身份；toString() 方便调试看 counts。它们是观察需要，既不生成贡献，也不参与合并规则。

## 6. 新增笔记，也会删除笔记

**假设**

新增三篇、删除一篇，想统计净增量 2。若把某分量从 3 直接减成 2，另一台设备还持有旧 3。

**问题**

max 会把减一撤销，能怎样复用已经写好的计数器？

**解释**

分别记录累计新增 P、累计删除 N，二者都是 GCounter；读数为 P.value()-N.value()。

PNCounter 的 increment 委托 P，decrement 委托 N，merge 分别合并两部分。构造器将两者绑定同一个本地 ID；返回新对象仍不改旧快照。

<details>
<summary>组合两种累计量</summary>

```java
public long value() {
    return Math.subtractExact(positive.value(), negative.value());
}

public PNCounter merge(PNCounter other) {
    return new PNCounter(positive.merge(other.positive), negative.merge(other.negative));
}
```

</details>

内部构造器接收更新后的两个计数器，参数校验与只读管理和前面保持一致。equals/hashCode 比这两部分复制信息。

## 本课任务顺序

先写 GCounter 的字段、构造器与 countOf；再写 increment、merge、value；最后补只读 state、equals/hashCode。它可用后，再组合成 PNCounter。

保留给业务层的边界：不能直接清零复用历史；PNCounter 不自动禁止负值，两边分别扣减同一个最后额度仍可能得到 -1。笔记是否存在、是否允许删除等校验不由计数器单独完成。
