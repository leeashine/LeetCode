# 第 2 步：`GCounter` / `PNCounter` —— 并发计数不丢

**目标**：5 台机器各自累加，最后加起来必须等于真实总数。

**大白话**：计数的难点是"两台机器同时 +1 会不会丢一个"。解法是**单写者原则**：每个副本只改自己那一格，别人的格子只读。

```
状态长这样（每个副本只动自己的格子）：
  副本A: {A=3}
  副本B: {B=1}
  副本C: {C=5}
  merge = 每个 key 取最大值 → {A=3, B=1, C=5}
  读数  = 所有格子求和      → 9
```

**为什么这样就对了**：
- 每个 key 只有一个"主人"，主人只会让它变大，所以**根本不存在冲突**（不需要解决冲突的冲突解决，才是最好的冲突解决）
- `merge` 取 max ⇒ 幂等（max(a,a)=a）、交换（max 可交换）、结合（max 可结合）
- 计数"和"是单调不减的，所以重复 merge 不会重复计数——**这是与"把值加起来当 merge"的关键区别**

## 你要写的 API

```java
public final class GCounter implements CvRDT<GCounter> {
    public GCounter(String replicaId);              // 空状态
    public GCounter increment();                    // 本地分量 +1
    public GCounter increment(long delta);          // delta<0 抛 IllegalArgumentException
    public long value();                            // 所有分量之和
    public long countOf(String replicaId);          // 未知返回 0
    public GCounter merge(GCounter other);          // 逐 key 取 max
    public Map<String,Long> state();                // 只读拷贝
}

public final class PNCounter implements CvRDT<PNCounter> {
    public PNCounter(String replicaId);
    public PNCounter increment();        // +1
    public PNCounter increment(long d);
    public PNCounter decrement();        // -1
    public PNCounter decrement(long d);
    public long value();                 // P.value() - N.value()
    public PNCounter merge(PNCounter other);
}
```

## 硬性不变量

- [ ] `GCounter.merge` 是**逐 key 取 max**，不是求和！（求和会破坏幂等）
- [ ] `state()` 不保留值为 0 的条目（规范形式）
- [ ] `equals` **只比较复制状态**（那个 Map），**不比较 `replicaId`**——`replicaId` 是本地身份，不是被复制的数据
- [ ] `PNCounter` = 两个 `GCounter`（正数一个、负数一个）。**为什么要两个？** 因为"减法"会破坏单调性；拆成两个只增计数器，就能在保持半格性质的同时支持减法

## 破坏性实验（一定要做，实测结果）

把 `GCounter.merge` 里的 `Math.max` 改成求和：

```java
long maximum = Math.max(countOf(entry.getKey()), entry.getValue());  // 改坏它
long maximum = countOf(entry.getKey()) + entry.getValue();           // 求和
```

实测：**8 个测试立刻挂掉**，横跨四个测试类——

```
✗ GCounterTest#threeReplicasConvergeRegardlessOfMergeOrder
✗ GCounterTest#mergeTakesMaximumPerReplicaRatherThanAddingRepeatedUpdates
✗ PNCounterTest#concurrentPositiveAndNegativeUpdatesConverge
✗ PNCounterTest#decrementGrowsSeparateNegativeComponentInsteadOfReducingPositiveComponent
✗ LatticeLawsTest#gCounterIsALattice
✗ LatticeLawsTest#pnCounterIsALattice
✗ ConvergenceTest#gCounterConverges
✗ ConvergenceTest#pnCounterConverges
```

**这一下你就彻底理解"幂等"为什么不是学术洁癖**：求和让重复投递把计数加了两遍，副本永远收敛不到一起。
