# 参考：AI Agents for Beginners 的课程组织

核对日期：2026-10-08。核对官方课程目录、学习指南、第 01、04 课及对应 Python Notebook，没有执行远端代码。下面先记录项目实际做法，再给出对本项目的建议。

## 它实际怎么教

- **围绕一个小 Demo 连接各课，并追问新增了什么能力。** 学习指南建议初学者先走基础课，用一个课程助手 Demo 连接工具、知识、计划等内容；每课后的复盘关注“现在比上一课多能做什么”。这是一条学习建议，不表示整个仓库的所有示例已经是同一个连续实现。[学习指南](https://github.com/microsoft/ai-agents-for-beginners/blob/main/STUDY_GUIDE.md)
- **先说这课解决什么、学完能做什么。** 第 01 课先列范围和学习目标，再解释 Agent、适用场景与组成；用旅行助手解释不同类型。它不是每一节都从故事开始。[第 01 课正文](https://github.com/microsoft/ai-agents-for-beginners/blob/main/01-intro-to-ai-agents/README.md)
- **代码分成小段，每段前交代用途。** 第 01 课 Notebook 依次连接服务、给旅行助手一个目的地查询工具、运行问答、展示流式回复。工具代码与调用代码已经写好，属于完整示例。[第 01 课 Notebook](https://github.com/microsoft/ai-agents-for-beginners/blob/main/01-intro-to-ai-agents/code_samples/01-python-agent-framework.ipynb)
- **先展开底层过程，再讲框架替你做了什么。** 第 04 课用“查某个城市现在几点”展示：把函数说明给模型 → 模型返回函数名和参数 → 程序执行函数 → 把结果交回模型。随后再介绍框架封装。正文在此之前仍有定义、用途与组件列表，并非全程“假设 → 问题 → 解释”。[第 04 课正文](https://github.com/microsoft/ai-agents-for-beginners/blob/main/04-tool-use/README.md)
- **同一个场景逐渐增加能力。** 第 04 课 Notebook 继续使用旅行助手，从查目的地扩展到查余位、查航班，再介绍工具审批等内容。查看的两个 Notebook 均没有 TODO 练习点；不能据此说它有“空骨架与答案分离”的练习路线。[第 04 课 Notebook](https://github.com/microsoft/ai-agents-for-beginners/blob/main/04-tool-use/code_samples/04-python-agent-framework.ipynb)

## 对 CRDT 教程的建议

以下是结合本项目学习需求的建议，不是对微软原文的转述。

1. **开头写一个具体结果。** 04 章可以写“学完后，能让手机和电脑同步备忘录：收到旧内容后修改，只留下新内容；断网分别修改，先保留两份”。比“理解版本向量”更容易判断自己学会没有。
2. **用同一份备忘录把本章讲完，跨章也尽量围绕一个离线笔记应用。** 标题引出 LWW/MV，标签引出 ORSet，正文引出 RGA；计数器可以解释操作次数统计。 每次只改变一个条件：先单机写入，再收到对方内容后写入，再两边断网写入。保持人物、内容和记录表一致，读者不用反复熟悉新例子。
3. **每个方法都由眼前的问题推出。** 例如“手机又改了一次，要留下什么证据？”引出本机次数加一；“两边交换记录，怎么避免忘掉已经收到的修改？”引出逐项取最大值；“哪份内容能安全删掉？”再引出比较方法。先说明输入、预期结果和判断依据，再出现方法名。
4. **每小节只多一种能力。** 借鉴 Notebook 的小段组织，但改为“假设 → 问题 → 解释 → 对应练习方法”。不要在最后突然给出整个类，也不要提前罗列一串尚未遇到需求的方法。
5. **讲解、练习、验证各有位置。** Markdown 解释设计来由并链接现有文件；`learnning` 保留方法签名和 TODO；完整实现作为参考；测试放在实际测试类，文档末尾只留运行入口。这种空骨架安排来自本项目的学习要求，不能说是微软这两课现成提供的。

优先借鉴的是“目标清楚、例子持续、小段可观察”。“从需求推导每个方法、学生亲手补空骨架”仍需要我们自己设计。
