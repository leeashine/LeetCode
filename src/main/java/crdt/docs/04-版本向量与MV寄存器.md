# 第 4 步：标题的两份独立修改，怎样都留下

[← 标题选一个值](03-LWW寄存器.md) ｜ [目录](../README.md) ｜ [下一章：给标签做增删同步 →](05-ORSet.md)

**上一步**：标题可以按标签选出一个赢家，但另一份独立修改会丢掉。

**本课任务**：区分“收到旧内容后再改”和“各自离线改”，只淘汰已被后续修改替换的标题。

**完成后**：前者留下一个值，后者保留两份；收到两份再保存一次，能回到一个值。

**练习入口**：[VersionVector](../learnning/VersionVector.java)、[MVRegister](../learnning/MVRegister.java)，只有声明和 TODO。第 09 章的 of 先留空。

**阅读约定**：本章只有两台设备：手机和电脑。后文把它们简记为 **A（手机）**、**B（电脑）**。“手机保存过 1 次、电脑保存过 0 次”简记为 **A1/B0**。第 3 节解释这张记录的来源，先记住写法即可。

## 1. 电脑先收到六点，再改七点

**假设**

事情按这个顺序发生：

```text
① 手机保存标题“六点吃饭”
② 手机同步给电脑，电脑收到“六点吃饭”
③ 电脑把标题改成“七点吃饭”
```

③ 在 ② 之后。电脑保存“七点”时，已经收到“六点”。

**问题**

为什么同步后只保留“七点”，而不保留两份？

**解释**

1. “七点”不是独立的修改。
2. 电脑收到“六点”之后，才保存“七点”。
3. “七点”替换了“六点”。
4. 只保留“七点”不会丢失修改。

“收到”只表示设备收到记录，不表示用户看过屏幕。

## 2. 两边断网，各自写了一个时间

**假设**

这次顺序不同。两台设备在同步之前各自保存：

```text
① 手机保存“六点吃饭”（此时手机没有收到过电脑的修改）
② 电脑保存“七点吃饭”（此时电脑也没有收到过手机的修改）
③ 两台设备联网，互相同步
```

② 是关键：电脑保存“七点”时，不知道“六点”存在。即使①在周一、②在周二，只要②发生时电脑没有收到①，两次修改就互相独立。判断标准是“保存时是否知道对方”，不是真实时间的先后。

**问题**

还能把“七点”当作“六点”的后续版本，直接删除“六点”吗？

**解释**

1. 不能。
2. 电脑保存“七点”时不知道“六点”。
3. “七点”没有包含“六点”的经历。
4. 删除“六点”会丢失一次真实的用户修改。
5. 本章保留两份，由应用或用户选择。
6. 上一章（LWW）只保留一个。两章是两种产品选择，不要混用。

## 3. 程序拿到同样两句话，怎样知道经过

**假设**

两种场景同步完成后，程序只有“六点”“七点”两个字符串。字符串不能说明：电脑保存“七点”前是否收到过“六点”。

**问题**

需要补充什么信息，才能区分两种场景？

**解释**

给每份内容附加一张**修改记录**。记录规则只有三条：

1. 每台设备占用固定的一栏。栏中的数字表示：这台设备保存过几次，而且这些次我都知道。
2. 本设备保存一次：本设备这一栏加一，其他栏不变。
3. 收到对方的记录：逐栏比较，每栏保留较大的数。

用这三条规则，重新演算两个场景。

**场景一（先收到再改）**

| 步骤 | 动作 | 产生/持有的记录 | 逐栏含义 |
| --- | --- | --- | --- |
| ① | 手机保存六点 | A1/B0 | 手机第 1 次保存；当时不知道电脑的修改 |
| ② | 电脑收到同步 | 学到 A1/B0 | 电脑知道手机保存过 1 次 |
| ③ | 电脑改成七点 | A1/B1 | 在 A1/B0 的基础上，电脑栏 0→1 |

**场景二（各自离线改）**

| 步骤 | 动作 | 产生的记录 | 逐栏含义 |
| --- | --- | --- | --- |
| ① | 手机保存六点 | A1/B0 | 手机第 1 次保存；不知道电脑 |
| ② | 电脑保存七点 | A0/B1 | 电脑第 1 次保存；不知道手机，手机栏仍是 0 |

对比两种场景的记录：

```text
场景一：六点 A1/B0，七点 A1/B1
  七点的每一栏都 ≥ 六点的对应栏（A 栏 1≥1，B 栏 1≥0），且 B 栏更多
  → 七点保存时已知道六点 → 六点过时，只保留七点

场景二：六点 A1/B0，七点 A0/B1
  六点有七点不知道的 A1，七点有六点不知道的 B1
  → 互不包含 → 两份都保留
```

判断依据只有一条：**逐栏比较两张记录**。

两个常见错误：

1. **不要比较次数总和。** 例：手机保存十次（A10/B0），也不知道电脑的 B1。总和不能回答“保存时是否知道对方”。
2. **栏位固定。** 每一栏始终代表同一台设备的 ID。同一张表在任何设备上含义相同。

## 4. 让这张记录支持创建、读取、推进和同步

**假设**

按上面的规则走一遍流程：开始时没有任何修改；手机第一次保存时，要先读出本设备的旧次数，才能加一；收到电脑的记录后，要学习它知道的次数。

**问题**

这些动作分别对应哪个方法？为什么会想到 empty、get、increment、merge？

**解释**

一个动作对应一个方法：

- 没有修改时，用 `empty()`。空 Map 表示“谁也不知道什么”。
- 保存前，用 `get(id)` 读本设备的旧次数。设备没有出现过时，返回 0。
- 保存时，用 `increment(id)`。本设备栏加一，返回新表。
- 收到对方的表时，用 `merge(other)`。每栏保留较大值。例：A2/B1 与 A1/B2 合并为 A2/B2。

在字段 TODO 定义 `SortedMap<String,Long> counters`，构造器复制后只读保存。每次更新都复制一张新表，返回新的 VersionVector。不要修改旧内容附着的记录：旧记录被修改后，第 3 节的判断会失效。

<details>
<summary>一次本地保存的核心变化</summary>

```java
long previous = get(replicaId);
SortedMap<String, Long> next = new TreeMap<String, Long>(counters);
next.put(replicaId, Math.addExact(previous, 1));
return new VersionVector(next);
```

</details>

片段前校验身份。溢出时不能回绕：回绕会把 A9 变成小数，被误判为旧记录。合并时从本设备的表复制，遍历对方的 key，写入较大次数。

相同的两张表，即使来自两个对象，也必须相等：equals/hashCode 比较 counters。asMap 便于观察，返回只读表。这是使用需要，不是新的修改操作。

## 5. 丢旧内容前，怎样问记录“已经过时了吗”

**假设**

沿用前面的数字：场景一里新七点是 A2/B1（电脑在已知 A1/B1 后又保存一次），旧六点是 A1/B0；场景二里的一对独立修改是 A1/B0 与 A0/B1。

**问题**

“过时”具体需要哪种比较？为什么不能只比一个数字？

**解释**

第 3 节的判断依据是逐栏比较。现在把它拆成三个问题，由浅到深：

1. `greaterOrEqual(other)`：**我的每一栏都不小于对方吗？** 只要有一栏小于对方，返回 false。两张相同的表也满足这个条件。
2. `dominates(other)`：**我包含对方，而且我比对方多吗？** 淘汰旧内容主要用它。
3. `isConcurrent(other)`：**两个方向都不包含吗？** 这就是第 2 节的独立修改。

用具体数字各算一遍（`左≥右` 表示 `左.greaterOrEqual(右)`）：

| 左 | 右 | 逐栏检查 | 左≥右 | 右≥左 | dominates | isConcurrent |
| --- | --- | --- | --- | --- | --- | --- |
| A2/B1 | A1/B0 | A:2≥1 ✓，B:1≥0 ✓ | 是 | 否（A:1<2） | 左淘汰右 | 否 |
| A1/B0 | A0/B1 | A:1≥0 ✓，B:0≥1 ✗ | 否 | 否（A:0<1） | 互相都不 | **是，两份都保留** |
| A1/B1 | A1/B1 | 每栏相等 | 是 | 是 | 否（相同不能淘汰） | 否 |

<details>
<summary>先写基本判断，再组合两个问题</summary>

```java
public boolean greaterOrEqual(VersionVector other) {
    for (Map.Entry<String, Long> entry : other.counters.entrySet()) {
        if (get(entry.getKey()) < entry.getValue()) return false;
    }
    return true;
}

public boolean dominates(VersionVector other) {
    return greaterOrEqual(other) && !other.greaterOrEqual(this);
}

public boolean isConcurrent(VersionVector other) {
    return !greaterOrEqual(other) && !other.greaterOrEqual(this);
}
```

</details>

null 输入校验放在基本方法前面。A2/B1 可以替换 A1/B0，B 栏相等不影响结果。规则是：每一栏都不落后，而且至少一栏更多。相同的表不能互相淘汰，否则同一次修改的重发会删除自己。

## 6. 设备知道两份，不等于旧内容写时知道两份

**假设**

同步后，手机知道 A1 和 B1 两次修改。但两份内容的记录不同：六点保存时只知道 A1，七点保存时只知道 B1。

**问题**

为什么每份内容都要带自己的记录？为什么不能把设备当前的总记录贴给所有内容？

**解释**

1. 假设把手机当前的总记录 A1/B1 贴给六点。
2. 六点就伪装成“保存时已知道七点”。
3. 第 5 节的 dominates 会误判六点过时。
4. 一次独立修改会被错误删除。

结论：**“保存时知道什么”和“现在知道什么”是两件事。记录必须跟随内容。**

所以定义 Entry：把 `VersionVector vv` 与 `T value` 绑在一起。再用 `Set<Entry<T>> entries` 保存所有未被替换的内容。

先填 Entry 的字段和构造器。HashSet 要识别同一次写的重发，Entry.equals/hashCode 比较“记录＋内容”。这要求第 4 节的表相等已经实现，否则同一张记录的两个对象会被当成两次修改。

T 在本章是 String。内容相同、记录不同，可以有两条 Entry。values 的可见集合只显示一次文字，所以 size=1 不证明只发生过一次修改。

## 7. 收到两份后，用户选择七点保存

**假设**

接着场景二：同步后，手机手里有两份候选（六点 A1/B0、七点 A0/B1）。用户看到两个标题，选择保留七点，在手机上再保存一次。这是手机的第 2 次保存。

```text
旧六点：A1/B0
旧七点：A0/B1
新七点：A2/B1   ← 这次保存要算出的记录
```

**问题**

新记录 A2/B1 从哪里来？为什么需要 version 和 assign 两个方法？

**解释**

分两步，一步对应一个方法：

1. `version()`：**先汇总经历。** 合并所有候选的记录。A1/B0 与 A0/B1 逐栏取大，得到 A1/B1。含义：本次保存前，我已知道所有这些修改。
2. `assign(value, id)`：**再推进本设备。** 把 version() 的结果执行 `increment("A")`。A 栏从 1 变 2，得到 A2/B1。新记录与新 value 绑定为一个 Entry。

检查结果：A2/B1 对旧六点（A1/B0）和旧七点（A0/B1）都满足 dominates。这次保存可以返回只含新 Entry 的状态，两份旧修改都被替换。empty() 提供起点：没有内容时 version() 是空表，assign 从 A1 开始。

<details>
<summary>按保存的需要依次补两个方法</summary>

```java
public VersionVector version() {
    VersionVector joined = VersionVector.empty();
    for (Entry<T> entry : entries) joined = joined.merge(entry.vv);
    return joined;
}

public MVRegister<T> assign(T value, String replicaId) {
    VersionVector next = version().increment(replicaId);
    Set<Entry<T>> assigned = new HashSet<Entry<T>>();
    assigned.add(new Entry<T>(next, value));
    return new MVRegister<T>(assigned);
}
```

</details>

MVRegister 构造器保存只读候选集合。注意两个边界：收到两份不会自动选择，只有再次保存才表达应用的选择；如果没有收到电脑的修改就再次保存，新记录不包含 B1，不能替换电脑的修改。

## 8. 联网收到标题，为什么不能当成又保存一次

**假设**

对方发来已存在的七点；之后，六点的旧消息还可能重发到达。接收只是复制对方的经历，不是本设备的新操作。

**问题**

怎样合并两组 Entry，又不把已经淘汰的旧标题带回来？

**解释**

接收使用 `MVRegister.merge(other)`，**不能使用 assign**。assign 会增加本地编号，把对方的修改伪装成本设备的新保存。merge 不增加编号，只做两步：

```text
① 两边 Entry 汇总到同一个集合（重发的相同 Entry 由 Set 去重）
② 对每个 candidate，检查其他 contender：
   若 contender.vv.dominates(candidate.vv)，candidate 已过时
③ 只保留没有被任何 contender 淘汰的 candidate
```

用新的结果 Set，不在正在遍历的集合中删除元素。

把第 7 节的结局代进去走一遍：

1. 手机已有“新七点 A2/B1”。六点的旧消息（A1/B0）重发到达。
2. 并集里有两个候选。
3. 检查六点：新七点的 A2/B1 dominates 它的 A1/B0，六点被剔除。
4. 检查新七点：没有候选能淘汰它。
5. 结果仍是 `[七点]`。旧消息重发不会造成回滚。

反过来，场景二中六点（A1/B0）与七点（A0/B1）合并：互相都不 dominates，两个候选都保留。

values 提取只读内容，size/isEmpty 方便页面查询。MVRegister.equals/hashCode 比较完整的 entries，不能只比较可见文字：可见文字相同、记录不同的两个状态，合并结果可能不同。

## 本课的三个小目标

先让次数表完成递增、合并和比较；再让容器完成本地保存；最后让两个独立标题合并，并检查新保存能淘汰旧消息。每个目标都来自前面的例子，不提前背整套 API。

完成后运行这段目标用法，每行都能对应一个动作：

```java
MVRegister<String> phone = MVRegister.<String>empty().assign("六点", "A");
MVRegister<String> computer = MVRegister.<String>empty().assign("七点", "B");
MVRegister<String> both = phone.merge(computer);
System.out.println(both.size());  // 2
MVRegister<String> chosen = both.assign("七点", "A");
System.out.println(chosen.values());  // [七点]
System.out.println(chosen.merge(phone).values());  // [七点]
```

对照正文读这段代码：前两条 assign 是场景二的①②；merge 后 size=2 是“独立修改都保留”；chosen 是第 7 节的“收到两份再保存”；最后一行是第 8 节的“旧消息重发仍被剔除”。

术语回顾：版本向量是“按来源记修改进度的表”；互不包含的修改叫并发，并发不要求同一秒；这个可保留多个值的容器叫 MVRegister。先会解释故事，再记术语。

代价：每个候选都附带一张记录，记录大小随设备数量增长；写入身份必须串行维护，不能从同一旧状态、用同一 ID 派生两次写；最终选择哪个内容，由应用决定。
