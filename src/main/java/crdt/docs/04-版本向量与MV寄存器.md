# 第 4 步：标题的两份独立修改，怎样都留下

[← 标题选一个值](03-LWW寄存器.md) ｜ [目录](../README.md) ｜ [下一章：给标签做增删同步 →](05-ORSet.md)

**上一步**：标题可以按标签选出一个赢家，但另一份独立修改会丢掉。

**本课任务**：区分“收到旧内容后再改”和“各自离线改”，只淘汰已被后续修改替换的标题。

**完成后**：前者留下一个值，后者保留两份；收到两份再保存一次，能回到一个值。

**练习入口**：[VersionVector](../learnning/VersionVector.java)、[MVRegister](../learnning/MVRegister.java)，只有声明和 TODO。第 09 章的 of 先留空。

## 1. 电脑先收到六点，再改七点

**假设**

手机写标题“六点吃饭”，同步到电脑；电脑收到后改成“七点吃饭”。

```text
手机写六点 → 电脑收到六点 → 电脑改成七点
```

**问题**

为什么可以只留七点，而不一直摆着两份？

**解释**

七点是在已经收到的六点基础上修改的，六点已经被替换。这里“收到”是设备同步到了记录，不保证用户认真看过屏幕。

## 2. 两边断网，各自写了一个时间

**假设**

手机写六点，电脑写七点；写之前谁也没收到对方。即使手机周一写、电脑周二写，电脑仍没收到六点。

**问题**

还能说七点是六点的后续版本，直接把六点删了吗？

**解释**

不能按上一节的理由删。本章选择两份都留下，由应用或用户决定。上一章可强行裁决，这里则保留独立修改；它们是不同产品选择。

## 3. 程序拿到同样两句话，怎样知道经过

**假设**

前两种经历都给程序带来六点、七点两个字符串，文字本身没说明电脑是否收到手机那份。

**问题**

需要补什么信息，才能区分先后修改和独立修改？

**解释**

每份内容附一张记录：写出它时，各设备的修改分别知道到第几次。设备每保存一次，自己的编号加一；同步会继承已经知道的编号。

```text
先收到再改：
六点：手机 1，电脑 0
七点：手机 1，电脑 1

各自离线改：
六点：手机 1，电脑 0
七点：手机 0，电脑 1
```

第一种的新记录没有漏掉旧经历，还多一次修改。第二种各有对方不知道的一次，所以都留。

不能只比较次数总和：手机改十次，也不表示收到电脑的一次。每一栏始终代表固定设备，不能在不同副本上解释成“我自己”。

## 4. 让这张记录支持创建、读取、推进和同步

**假设**

开始没有修改；手机保存要读自己旧次数再加一；收到电脑记录后又要继承它知道的修改。

**问题**

为什么会想到 empty、get、increment、merge？

**解释**

按动作依次引出方法：

- 从没有经历开始，需要 empty；空 Map 足够表示它。
- 下一次修改要知道旧编号，需要 get(id)，缺失返回 0。
- 自己保存一次，需要 increment(id)，只改自己那栏。
- 收到另一张表，需要 merge(other)，同一来源取 max。

在字段 TODO 定义 `SortedMap<String,Long> counters`，构造器复制后只读保存。每个更新拷贝表、返回新 VersionVector，不修改旧内容附着的记录。

<details>
<summary>一次本地保存的核心变化</summary>

```java
long previous = get(replicaId);
SortedMap<String, Long> next = new TreeMap<String, Long>(counters);
next.put(replicaId, Math.addExact(previous, 1));
return new VersionVector(next);
```

</details>

片段前校验身份；溢出时不能回绕。合并则从自己的表拷贝，遍历对方 key，写入较大次数。

相同表即使来自两个不同对象也应该相等：equals/hashCode 比 counters。asMap 便于观察，返回只读表。这是使用需要，不是新增一种修改。

## 5. 丢旧内容前，怎样问记录“已经过时了吗”

**假设**

新七点是 A2/B1，旧六点是 A1/B0；另一对独立修改是 A1/B0 与 A0/B1。

**问题**

具体需要哪种比较，为什么不能只比一个数字？

**解释**

先问“我的每栏都不落后吗”，产生 greaterOrEqual；任意栏小于对方就 false。

这还包括完全相同的表。淘汰旧值要问“我包含它，而且确实更多吗”，再产生 dominates。最后 isConcurrent 方便判断两边都没包含对方。筛旧内容主要用 dominates。

<details>
<summary>先写基本判断，再组合两个问题</summary>

```java
public boolean greaterOrEqual(VersionVector other) {
    for (Map.Entry<String, Long> entry : other.counters.entrySet()) {
        if (get(entry.getKey()) < entry.getValue()) return false;
    }
    return true;
}

public boolean dominates(VersionVector other) {
    return greaterOrEqual(other) && !other.greaterOrEqual(this);
}

public boolean isConcurrent(VersionVector other) {
    return !greaterOrEqual(other) && !other.greaterOrEqual(this);
}
```

</details>

null 输入校验放在基本方法前面。A2/B1 能替换 A1/B0，即使 B 栏有时相等也可以；不要求每一栏都更大。相同表不能互相淘汰。

## 6. 设备知道两份，不等于旧内容写时知道两份

**假设**

手机同步后知道了 A1 和 B1，但六点写出时只知道 A1，七点写出时只知道 B1。

**问题**

为什么每份内容都要带自己的记录，不能全贴同一个总进度？

**解释**

否则会把两份旧内容伪装成写出时已收到对方。用 Entry 将 VersionVector vv 与 T value 绑在一起，再用 Set<Entry<T>> entries 保存尚未被替换的内容。

先填 Entry 的字段和构造器。HashSet 要能识别同一次写的重发，Entry.equals/hashCode 比“记录＋内容”；次数表的相等也要先实现。

T 在本章是 String。内容相同、记录不同可以有两条 Entry，values 的可见集合却只显示一次文字，因此 size=1 不证明只发生一次修改。

## 7. 收到两份后，用户选择七点保存

**假设**

手机已经知道 A1/B1，用户选择七点，进行手机第 2 次保存。

```text
旧六点：A1/B0
旧七点：A0/B1
新七点：A2/B1
```

**问题**

新记录从哪里来？为什么需要 version 和 assign？

**解释**

保存动作产生 assign(value,id)，但它先得知道当前所有候选的经历。因此先抽出 version()，将各 Entry.vv 合并成总记录；再 increment(id)，与新 value 绑定成一个 Entry。

这个新记录严格包含当前所有旧记录，可以直接返回单候选状态。empty 让没有内容时也有起点。

<details>
<summary>按保存的需要依次补两个方法</summary>

```java
public VersionVector version() {
    VersionVector joined = VersionVector.empty();
    for (Entry<T> entry : entries) joined = joined.merge(entry.vv);
    return joined;
}

public MVRegister<T> assign(T value, String replicaId) {
    VersionVector next = version().increment(replicaId);
    Set<Entry<T>> assigned = new HashSet<Entry<T>>();
    assigned.add(new Entry<T>(next, value));
    return new MVRegister<T>(assigned);
}
```

</details>

MVRegister 构造器保存只读候选集合。收到两份并不会自动决定；再保存才表达应用的新选择。没收到电脑那份就再写一次，依然不能替它作决定。

## 8. 联网收到标题，为什么不能当成又保存一次

**假设**

对方发来已存在的七点；后来六点的旧消息还可能重发。接收不是本设备新的用户操作。

**问题**

怎样合并两组 Entry，又不把旧标题带回来？

**解释**

接收产生 MVRegister.merge(other)，不用 assign，不增加本地编号。先并集去重，然后对每个候选找有没有记录严格包含它的另一项。

```text
两边 Entry 先汇总
逐个 candidate 检查其他 contender
若 contender.vv.dominates(candidate.vv)，candidate 已过时
只将没有后继的 candidate 放入新结果
```

用新的结果 Set，不在正遍历的集合中删。并发项都没被包含，所以都留；A2/B1 到来后，旧六点重发仍会被剔除。

values 提取只读内容，size/isEmpty 方便页面查询；MVRegister.equals/hashCode 比完整 entries，不能只比可见文字。状态里隐藏的经历会影响下一次合并。

## 本课的三个小目标

先让次数表完成递增、合并和比较；再让容器完成本地保存；最后让两个独立标题合并，并检查新保存能淘汰旧消息。每个目标都来自前面的例子，不提前背整套 API。

完成后运行这段目标用法，每行都能对应一个动作：

```java
MVRegister<String> phone = MVRegister.<String>empty().assign("六点", "A");
MVRegister<String> computer = MVRegister.<String>empty().assign("七点", "B");
MVRegister<String> both = phone.merge(computer);
System.out.println(both.size());  // 2
MVRegister<String> chosen = both.assign("七点", "A");
System.out.println(chosen.values());  // [七点]
System.out.println(chosen.merge(phone).values());  // [七点]
```

版本向量是“按来源记修改进度的表”；互不包含的修改叫并发，不要求同一秒；这个可保留多个值的容器叫 MVRegister。先会解释故事，再记术语。

代价是每个候选都带随设备数量增长的记录；写入身份也要串行维护，不能从同一旧状态用同一 ID 独立派生两次写。最终怎么选内容仍由应用决定。
