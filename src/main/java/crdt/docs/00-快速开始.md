**本课任务**：先认识应用场景，观察已有演示，再找到自己要填写的练习骨架。

## 1. 两边都有“周末计划”这份笔记

**假设**

手机 A 和电脑 B 各保存同一份笔记：

```text
标题：周末计划
标签：旅行
正文：ab
```

断网后，手机修改标题，电脑添加标签；还有操作统计记录各处做过几次修改。

**问题**

联网以后，是把手机整份盖到电脑上，还是把电脑整份盖到手机上？

**解释**

直接覆盖会丢掉另一边的修改。我们将分别实现这些部件的合并：统计要不丢不重，标题要定义取舍，标签要保存删除证据，正文还要保持顺序。

同一份逻辑笔记存到两处，就有两个副本。本课程把副本当作普通 Java 对象，A/B 是写入身份；不同设备不能随意共用同一个身份。

## 2. 两边显示一样，不代表经历一样

**假设**

手机独自做了三次操作，电脑独自做了三次操作；另一种情况下，电脑只是复制手机那三次。两种情况下屏幕都可能显示 3。

**问题**

光发一个 3，接收方怎么知道应该保留 3 还是汇总成 6？

**解释**

不知道。所以内部要多记录操作来源。显示结果是给用户看的；复制状态保留合并需要的信息。

这个区别会贯穿后面：标题带修改记录，标签带添加身份，正文带字符身份。它们不是为了堆字段，而是回答裸值无法回答的问题。

## 3. 本地按保存，与收到别人修改

**假设**

你在手机点保存，手机立即产生新状态。稍后同步程序把它送到电脑，电脑用自己的当前状态合并它。

**问题**

它们为什么不是同一个操作？调用 merge 会自动联网吗？

**解释**

保存是生成新的本地修改；合并是处理已经存在的信息，不应凭空再生成一次用户操作。

```text
用户保存 → 本地更新方法 → 新状态
网络送达 → 接收方 merge → 合并状态
```

merge 在本仓库里只是方法调用，不发送消息。对象不可变，返回值需要接住：`a = a.merge(b)`。这样不会顺手修改 b，也能留下旧快照检查乱序。

## 6. 开始之前说清这三个前提

- 每个写入身份串行维护自己的历史；丢掉计数后不能随意复用同一 ID。
- 同步必须最终把更新信息送到各个目标；正确的 merge 不能弥补永远没送达的信息。
- 本课实现数据结构，用对象合并模拟网络；持久化、成员管理与真实网络协议是后续工作。

“CRDT”是这种按规定更新、合并即可收敛的数据类型的名称。下一章先从简单标签并集认识规则，再慢慢引出其他术语。
