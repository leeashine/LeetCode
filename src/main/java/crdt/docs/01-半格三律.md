# 第 1 步：先立规矩 —— 半格三律

**目标**：写下一个接口，把"合格的 merge"钉死。这一步不写业务逻辑，只写契约。

**大白话**：所有 CRDT 的共同点不是"长什么样"，而是"merge 满足什么"。先把规矩立好，后面 8 步都是在填这个规矩的具体实现。

## 你要写的 API

```java
package crdt;

public interface CvRDT<T extends CvRDT<T>> {
    T merge(T other);   // 半格上的 join：幂等、交换、结合
}
```

## 硬性不变量

- [ ] 实现类**不可变**：`merge` 返回新实例，绝不修改 `this`，也绝不修改 `other`
- [ ] 实现类必须正确实现 `equals`/`hashCode`——第 7 步的收敛性断言全靠它

> **为什么强制不可变？** 因为这样"三律"才能直接用 `assertEquals` 断言。可变对象会让"两个副本是否一致"变成一笔糊涂账，小白最容易在这里翻车。

## 自检问答

1. 为什么"幂等"能省掉消息去重？（答：重复 merge 同一个状态，结果不变，所以重发是免费的）
2. 为什么"结合"能让消息经多跳转发？（答：中转节点只需 merge 再转发，中间结果不会污染最终结果）
