## 1. 大家都空了，也算一致吗

**假设**

错误 merge 无论收到什么都返回空标签。最终手机、电脑都空了。

**问题**

只断言两边相等，能发现丢数据吗？

**解释**

发现不了。必须另算期望的可见结果：计数要等于独立贡献，标签要符合已见删除和未见添加，正文要有正确字符及顺序。

因此每个用例有两类结果：复制状态相等，以及具体统计/标签/正文正确。equals 比哪些字段依类型而定，不把所有可见内容相等都当成同步完成。

## 2. 先少量操作，画完整传播路线

**假设**

手机 A 记两次、电脑 B 记三次。第一次 A→B 没送到，B→A 送到了；接着两边各再记一次。

| 步骤 | 手机记录 | 电脑记录 |
|---|---|---|
| 各自操作 | A2 | B3 |
| A→B 丢失 | A2 | B3 |
| B→A 成功 | A2/B3 | B3 |
| 两边各继续一次 | A3/B3 | B4 |
| 再同步并重发 | A3/B4 | A3/B4 |
```text
最后应是 3 + 4 = 7
```

**问题**

丢掉的消息一定得按原操作重放吗？为什么旧 A2 再来不应改变结果？

**解释**

完整状态会携带已知历史。新的 A3 仍包括 A 的前两次贡献，所以重试新状态可以补齐；旧 A2 无法把 A3 顶回去。幂等保证重发安全，重试负责最终送达。

把这条时间线写成几次 merge，保留 delayedPhone 旧快照，随后故意让它晚到。先算 7，再读现有用例中的断言。

## 3. 哪一条操作是在模拟网络

**假设**

测试里没有真实网络，只保存几个状态对象，再按选定顺序合并。

**问题**

丢包、重发、旧快照分别怎样表达，为什么不用先搭服务器？

**解释**

丢包就是跳过一次 merge；重发是同一状态合并两次；乱序旧消息是先保存旧对象，晚一点才 merge。不可变快照让这个过程可复现。

```java
GCounter delayed = phone;       // 留下旧快照
// 此处没有让电脑 merge(phone)，模拟未送达
phone = phone.merge(computer);  // 另一方向送达
computer = computer.merge(delayed).merge(delayed); // 旧消息重发
```

这段只是传播动作示意，最终值还要按具体时间线算。修改本地状态的 increment/add/insert 与收到状态的 merge 分开；一个同步调用不应该被统计成新的用户操作。

## 4. 三律的测试为什么还要选边界

**假设**

标题平局时保留自己的错误实现，却只拿编号 1 与 2 做测试，始终没有平局。

**问题**

写过“换方向一样”就代表所有合法状态都对了吗？

**解释**

不代表。应该专门构造同编号、不同来源；也检查重复状态、空状态、三份状态的不同分组。

参考目录的 LatticeLawsTest 与 ConvergenceTest 有更多样本和固定随机种子，可作为进阶阅读。学习用例先选少量确定轨迹，失败能直接重放；随机测试再扩展覆盖，有限测试不叫数学证明。

## 5. 增加一条能检验自己理解的轨迹

**假设**

已有测试覆盖统计的丢包重试、标签的并发添加和正文墓碑后代。你想再检查旧快照晚到。

**问题**

新增用例该先想方法名，还是先想一段故事？

**解释**

先想故事并算结果。例如 S 写好 ab，A 删除 b，B 在 a 后插 X；同步后应是 aX，再送旧 ab 仍是 aX。

```
输入：共享 ab，以及两次离线修改
动作：先送删除后的状态，再送插入状态，最后送旧 ab
期望：两边状态相等，text 都是 aX
```

这才写一个 @Test，用 assertEquals 同时检查两件事。不是先堆随机循环，再仅断言非空。

## 读已有测试时追三件事

每个状态来自哪一次本地修改？哪条消息还没送到？哪些信息决定期望结果？沿着它们理解局部变量、合并顺序和断言，就能独立添加一种轨迹。

持续新写、任意长断网、旧备份恢复、GC 后再写并没有因这几个用例自动安全。遇到分歧先看各处是否收到相同信息，再查更新、合并和查询各自规则。
